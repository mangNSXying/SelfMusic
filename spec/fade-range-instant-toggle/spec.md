# Feature Specification: 淡入淡出时长范围调整 + 播放/暂停按钮即时响应

**Created**: 2026-10-04  
**Status**: Draft  
**Input**: User description: "播放设置中的'淡入淡出'选项，时长范围改成0.5~2s，然后修改一下播放暂停按钮的UI行为：当前点击暂停或播放按钮后，需要过完淡入淡出时间后才变成暂停或播放状态"

## Overview

本特性包含两项对现有播放体验的调整：（1）播放设置中"淡入淡出"的可调时长范围从 1~3 秒改为 0.5~2 秒；（2）播放/暂停按钮改为**点击后立即翻转状态**——不再等待淡入淡出渐变结束，音频渐变在后台继续完成，渐变进行中再次点击可反向打断。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 点击播放/暂停按钮立即翻转（Priority: P1）

用户在播放页（竖屏或横屏）或迷你播放条上点击播放/暂停按钮，按钮图标应**立即**切换为目标状态（播放中↔已暂停），与淡入淡出是否开启、时长多长无关。音频本身仍按设定时长平滑渐变：暂停方向先淡出再真正暂停；播放方向立即开始出声并淡入。

**Why this priority**: 这是本次变更的核心痛点——当前点击暂停后按钮要"卡"整个淡出时长才变化，用户会以为没点到而重复点击。立即反馈是交互正确性的基础。

**Independent Test**: 开启淡入淡出（时长设 2s）播放歌曲，点击暂停按钮，观察按钮图标是否立刻变为"播放"图标且音乐在约 2 秒内渐弱至无声；再点击播放，图标立刻变回"暂停"图标且声音渐起。

**Acceptance Scenarios**:

1. **Given** 淡入淡出开启（时长 2s）且正在播放，**When** 用户点击暂停按钮，**Then** 按钮图标在一帧内（无感知延迟）变为播放图标；音频在约 2s 内淡出，淡出结束后播放实际停止
2. **Given** 淡入淡出开启（时长 2s）且处于暂停，**When** 用户点击播放按钮，**Then** 按钮图标在一帧内变为暂停图标；音频立即开始播放并从无声渐入至正常音量
3. **Given** 淡入淡出关闭，**When** 用户点击播放/暂停按钮，**Then** 按钮立即翻转且播放/暂停立即生效（与现状一致）
4. **Given** 上述任一操作发生在迷你播放条按钮上，**Then** 迷你播放条按钮与播放页大按钮状态保持一致且均立即翻转

---

### User Story 2 - 渐变进行中反向打断（Priority: P2）

淡出（或淡入）尚未结束时，用户再次点击按钮，不应被忽略，而应立即反向：淡出中点击→取消暂停意图，音量从当前值平滑恢复，按钮立即变回"播放中"；淡入中点击→从当前音量平滑淡出后暂停，按钮立即变为"已暂停"。

**Why this priority**: 按钮即时响应后，若渐变期间点击仍被忽略，会出现"按钮变了但点了没反应"的新问题；反向打断保证任意时刻点击都有符合直觉的反馈，是即时响应的必要配套。

**Independent Test**: 播放中点击暂停后，在淡出结束前（如 0.5s 内）再点击一次，观察按钮立即变回播放中、音量从当前位置渐回而不是静默重启。

**Acceptance Scenarios**:

1. **Given** 淡出进行中（音频尚未真正暂停），**When** 用户点击播放按钮，**Then** 按钮立即显示"播放中"，取消原暂停意图，音量从当前值平滑回升至正常，播放不中断、无需重新加载
2. **Given** 淡入进行中，**When** 用户点击暂停按钮，**Then** 按钮立即显示"已暂停"，音量从当前值平滑淡出后真正暂停
3. **Given** 用户在 2s 内连续快速点击按钮多次，**Then** 每次点击都被响应且方向交替，最终状态与点击次数奇偶性一致，不出现卡死、状态错乱或无响应窗口

---

### User Story 3 - 淡入淡出时长范围 0.5~2s（Priority: P3）

用户在设置→播放中调整"淡入淡出"时长时，滑条范围为 0.5~2 秒，可精细调节并实时预览，设置持久化。

**Why this priority**: 独立于按钮交互的小改动，独立可测，不影响其他故事交付。

**Independent Test**: 打开设置页淡入淡出时长滑条，验证最小 0.5s、最大 2s、步进 0.1s；调整后杀掉应用重开，时长保留。

**Acceptance Scenarios**:

1. **Given** 用户打开播放设置中的淡入淡出时长滑条，**When** 拖动滑条，**Then** 可选范围为 0.5~2.0s，步进 0.1s，标签实时显示一位小数（如"1.2 秒"）
2. **Given** 用户把时长设为 0.5s 并退出应用，**When** 重新打开应用，**Then** 时长仍为 0.5s 且实际暂停/恢复渐变按 0.5s 生效
3. **Given** 历史版本保存的时长超出新范围（如 3000ms），**When** 读取该设置用于渐变或滑条显示，**Then** 按最近的边界值（2000ms）生效/显示，不崩溃、不出现超范围渐变

---

### Edge Cases

- 淡入淡出开关关闭时：所有行为退化为立即切换，无渐变（与现状一致）
- 快速连续点击（含 2s 时长内的 3 次以上交替点击）：每次点击必须被响应且状态一致，不允许出现"点击被吞"或状态与图标不符
- 反向打断发生在淡出极早期（音量≈1）或极末期（音量≈0）：音量过渡仍平滑，不出现爆音或长时间无声
- 渐变进行中切歌/上一首/下一首：沿用现有切歌逻辑（渐变定时器随新曲装载被取消），新曲正常起播
- 非按钮触发的暂停（睡眠定时到点、曲目自然结束、通知栏"暂停/停止"）：淡出后暂停的既有行为不变；通知栏/系统媒体中心的播放状态同步时机保持现状（实际状态变化后同步）
- 淡入淡出开关或时长在播放中被修改：沿用现有"应用音频设置即重建播放器并恢复"的机制，不因本特性额外改变
- Web/桌面/鸿蒙/Android 各平台：立即翻转与反向打断行为一致（渐变本身为软件音量渐变，全平台可用）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 设置页"淡入淡出"时长滑条范围 MUST 为 0.5~2.0 秒，步进 0.1 秒，标签实时显示一位小数值
- **FR-002**: 系统 MUST 以毫秒持久化时长设置，并在读取时将越界值钳制到 [500, 2000]ms 后使用；默认值保持 2000ms
- **FR-003**: 点击播放/暂停按钮后，应用内所有播放/暂停指示（播放页竖屏/横屏大按钮、迷你播放条按钮）MUST 在 100ms 内翻转为点击所指向的目标状态，且与淡入淡出设置无关
- **FR-004**: 暂停方向：按钮翻转后音频 MUST 继续按设定时长淡出，淡出结束后才执行实际暂停；对外（断点保存、媒体通知状态）以实际暂停完成为准
- **FR-005**: 播放方向：按钮翻转后音频 MUST 立即开始播放并按设定时长从低音量淡入至正常
- **FR-006**: 渐变进行中再次点击按钮 MUST 反向打断：淡出中点击恢复播放（从当前音量平滑回升，不重新加载音源）；淡入中点击进入淡出暂停（从当前音量平滑下降）；两次点击之间不允许存在被忽略的窗口
- **FR-007**: 淡入淡出开关关闭时，点击播放/暂停 MUST 立即切换且无渐变（保持现状）
- **FR-008**: 非按钮触发的淡出暂停路径（睡眠定时到点、曲目结束、通知栏暂停/停止）MUST 保持既有行为，不受按钮即时化影响
- **FR-009**: 项目文档（settings.md 及相关设计文档）中淡入淡出时长的范围描述 MUST 同步更新为 0.5~2s

### Key Entities *(include if feature involves data)*

- **淡入淡出设置**（既有实体，范围变更）：`fadeEnabled`（开关）、`fadeDurationMs`（时长，毫秒，有效域收敛为 [500, 2000]，默认 2000）
- **播放器状态**（本特性引入的语义区分）：*目标/界面状态*（用户点击后立即生效、驱动按钮图标）与*实际播放状态*（音频引擎的真实播停，渐变结束后达成）；两者在渐变期间允许短暂不一致，其余时刻必须一致

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 淡入淡出开启且时长为最大值 2s 时，点击暂停/播放后按钮图标在 100ms 内完成翻转（10 次操作 100% 达标）
- **SC-002**: 渐变期间的反向点击 100% 得到响应并立即翻转图标，连续 5 次快速交替点击后状态与图标始终一致
- **SC-003**: 时长滑条在 0.5~2.0s 内可调（16 档），设置后重启应用保留；实际渐变时长与设定值偏差不超过一个渐变周期（±16ms 级别，感知上无差别）
- **SC-004**: 淡出的音频渐变体验不变：暂停后声音按设定时长平滑减弱至无声，无突然中断、无爆音

## Assumptions

- 滑条步进取 0.1s：新范围较窄，0.1s 粒度与现有"一位小数"显示格式天然对齐（当前 1~3s 为 0.5s 步进，在新范围下仅 4 档过粗）
- 历史越界存储值（如 3000ms）采取"读取时钳制"策略，不做存储迁移；用户下次拖动滑条即写回合法值
- 系统通知栏/媒体中心（AVSession 等）的播放状态同步时机保持现状：在实际播放状态变化后同步，渐变期间允许通知栏状态短暂滞后于应用内按钮
- 渐变实现沿用现有软件音量渐变（约 16ms 周期），不引入音频后端 crossfade
- 播放页大按钮当前直接订阅播放器状态流的实现方式可调整为实现需求的手段之一，属实现细节，规格不约束
- 断点续播保存时机不受本特性影响（仍以实际播放状态为准）
